# P1-COMPILER-F01 可测试性说明

> Revision：`TEST-SEAM-R04@7421b050ed44`。输入：`REQAN-R04@7421b050ed44`。

## 1. 必须注入的接缝

- `DocumentSourceProvider`：内存、classpath、受控测试文件系统；
- `DocumentFrontend`：XML/YAML 安全前端；
- `MixSourceResolver`：不直接调用全局 ClassLoader；
- `RawDefinitionBuilder`：按 definition kind 单独验证；
- `InformationExpressionParser`：输出 token/AST 与 SourceRef，不在 P1 求值；
- `InformationKeyResolver`：可注入 System/Information SymbolTable；
- `ModelAccessSelectorResolver`：分别测试 target-main、property path、多 ref 和冲突；
- `CompilerPass`：可单独执行并观察输入、输出、Diagnostic；
- `RegistryBuilder`：发布前可冻结并验证不可变；
- `DigestStrategy`：固定版本，source/semantic digest 分离；
- `ContextPublisher`：以测试替身验证原子切换；
- `Clock/Timer`：只用于指标，不进入语义摘要。

## 2. 实物 fixture 基线

对 `dec-demo/src/main/resources/mix` 固定：

- XML 文件 10；
- Data 5；View 2；System 4；RuleView 14；BusinessScope 1；
- Information 16：user 3、order 6、payment 5、common 2；
- Directory 5；Action 8；Produce 4；
- System→Rule 文件边 3；
- `common` 无 Data/View/RuleView/ModelAccess；
- `common.paySuccess` 依赖 `payment.success` 与 `order.paySuccessStatus`；
- `common.payError` 依赖 `payment.error` 与 `order.payErrorStatus`；
- `OrderInfo.user` 通过 `UserInfo(target-main=user)` 显式映射。

数量只用于 fixture 回归；合法新增配置必须显式更新清单和测试，不作为生产容量上限。

## 4. 测试分层

1. **纯单测**：Key、expression parser、selector resolver、Diagnostic 排序、digest；
2. **Compiler contract**：内存 SourceGraph、Raw builder、Pass、Deferred；
3. **Fixture contract**：真实 `mix` 主资源和测试资源一致性；
4. **Frontend security**：XML/YAML 与 URI/路径边界；
5. **Concurrency/atomicity**：Session 隔离、失败不替换 Context；
6. **Architecture**：模块依赖、parser/runtime 隔离、无 demo 反向依赖；
7. **Retirement scan**：目录、POM、dependency tree、ServiceLoader、反射和 artifact。
